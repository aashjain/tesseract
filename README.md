# AG Designs — The AG Tesseract

An immersive, scroll-led storytelling website for AG Designs, built from
`AG_Designs_Concept_01_Tesseract.pdf` and the production plan in `prompt.txt`.

The homepage is one continuous story in twelve scenes: a visitor starts inside
fragmented brand activity, passes through the **A** of the AG monogram as an
aperture, explores the connected system behind it, meets the work and the people,
and leaves as every earlier element aligns onto the **G** — the orbit the system
settles into once it has gravity.

It is also, at every moment, an ordinary fast website. The WebGL layer is
progressive enhancement; it never holds the only copy, navigation or call to
action.

### The story clock

One GSAP `ScrollTrigger` scrubs native vertical scroll into a single normalised
progress value. That value is written to a plain mutable object
(`src/lib/experience/progress.ts`), **not** React state — the camera and every
scene read it inside `useFrame`, so scrolling never triggers a render.

Scene order, lengths, world positions and asset packages live in
`src/lib/experience/sceneManifest.ts`. Nothing in the CMS can move a camera,
reorder the narrative or inject geometry.

Two layout rules are load-bearing and easy to break by accident:

- **Every scene weight must be greater than 1.** A sticky reading zone is pinned
  for `weight - 1` viewports; at weight 1 it is never pinned and the copy scrolls
  out from under its own scene. A unit test enforces this.
- **The last section carries one extra viewport.** ScrollTrigger measures
  `railHeight - viewportHeight`, so without that tail every section would sit
  slightly ahead of the scene its camera is playing, and the error would compound
  down the page.

## The brand contract

`public/brand/source/` holds the supplied files, untouched and committed:

- `ag-logo.svg` — the authoritative artwork, `viewBox="0 0 3750 3750"`
- `ag-logo-transparent.png` — the 5000 × 5000 reference raster

Everything else is derived from them:

- `src/lib/brand/paths.ts` carries the two approved monogram paths verbatim. A
  unit test asserts they are still byte-identical to the source SVG, so a
  "tidied" coordinate or a redrawn corner fails the build.
- `src/lib/brand/generated/agLogoMarkup.ts` is generated by
  `node scripts/derive-brand.mjs`. Rendering the mark inline (rather than as an
  `<img>`) is what lets it inherit `currentColor` on the dark surface.
- `src/lib/three/logoGeometry.ts` turns those paths into scene geometry. Only
  three transforms are applied, all silhouette-preserving: centre on the glyph's
  own bounding box, rotate a half turn about X, uniform scale.

Two details worth knowing before editing that file:

- The half turn about X is deliberate. Correcting SVG's downward Y axis with a
  negative Y scale mirrors the mesh, reverses triangle winding and leaves every
  normal facing away from the camera — the mark then renders as an unlit
  silhouette. A unit test guards this.
- The A's counter-space is real geometry, not a mask. The camera flies through
  the actual hole in the supplied path.

**Still needs client approval:** colour use on the isolated A and G, minimum
size, clear space, and whether the curved `designs` wordmark detail may be hidden
at small sizes (the code already has the documented monogram-only variant, used
in the header).

## Experience tiers

Chosen by capability detection, never user-agent sniffing
(`src/lib/experience/capabilityDetection.ts`):

| Tier | When | What runs |
|---|---|---|
| `full` | Large screen, capable device | Full camera path, all effects, pointer parallax |
| `balanced` | Constrained laptop / integrated GPU | Same twelve scenes, reduced geometry and DPR |
| `mobile` | Coarse pointer or narrow viewport | Simplified scenes, ~27% shorter scroll, no parallax |
| `reduced` | `prefers-reduced-motion` | No canvas, no scrubbed camera, full story as HTML |
| `fallback` | Save-Data, no WebGL, repeated context loss, or user choice | Same, plus a still frame per scene |

All five carry the same copy order, capability links, project links and CTA.
The visitor can switch to the semantic presentation from the first viewport
(`Explore normally`) and back again; the choice is remembered for the session.

The quality controller (`AdaptiveQuality`) samples frame time once the scene has
settled and steps *down* only — device pixel ratio first, then particle counts,
then post-processing. Two context losses or a sustained sub-24 fps frame rate
hand control to the semantic tier rather than showing an error.

## Content

All content flows through one boundary, `src/lib/content/repository.ts`. Today it
resolves to typed local fixtures in `src/lib/content/fixtures.ts`.

**Every project, person, metric and image shipped in this build is a clearly
labelled placeholder.** Fixture projects carry `status: 'fixture'`, which renders
a visible "sample content" notice on the case study and in the project portal.
Nothing claims a real client, testimonial or result, and no project carries a
numeric outcome — the model requires a value, unit, context, source and
measurement date for every figure.

### Replacing the fixtures

Edit `src/lib/content/fixtures.ts`, or wire a CMS. The types in
`src/lib/content/types.ts` are the contract; route components only ever see
`ContentRepository`, so swapping the source needs no page changes.

To connect Sanity: install `next-sanity`, implement `ContentRepository` against
it, and set the environment variables below. `getContentRepository()` currently
throws a descriptive error if the credentials are present but the adapter has not
been installed — that is intentional, so a half-configured deploy fails loudly
instead of quietly serving placeholders.

### Environment variables

Copy `.env.example` to `.env.local`.

| Variable | Required | Purpose |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | For production | Canonical origin for metadata and social cards |
| `NEXT_PUBLIC_SANITY_PROJECT_ID` | No | Switches the repository to the Sanity adapter |
| `NEXT_PUBLIC_SANITY_DATASET` | No | Sanity dataset name |
| `SANITY_API_READ_TOKEN` | No | Draft mode / visual editing |
| `CONTACT_WEBHOOK_URL` | Before launch | Where enquiries are POSTed. **Unset by default: the form validates and confirms but delivers nowhere.** |
| `NEXT_PUBLIC_SENTRY_DSN` | No | Error and context-loss monitoring |

## Replacing the art

Nothing in the 3D layer is downloaded stock content — every scene is procedural
geometry built from primitives, instanced meshes, splines and the approved logo
paths. That keeps the 3D payload at zero bytes and makes replacement additive
rather than destructive.

- **Scene geometry:** each scene is one self-contained component in
  `src/components/three/scenes/`. Drop a `useGLTF` load in place of the
  procedural block; the camera path, lighting and timing are unaffected.
- **Materials:** shared in `src/lib/three/materials.ts` so the world reads as one
  lit space. Prefer editing these over adding per-scene materials.
- **Still frames (Tier D):** `node scripts/generate-posters.mjs` regenerates the
  abstract SVG posters in `public/media/posters/`. Replace them with real
  photography by pointing the fixtures at new files.
- **Portraits and project imagery:** currently `null` or placeholder posters. The
  content model requires alt text on every image.

### 3D renders we would like from you

The build is complete and shippable as it stands. These are the places where a
supplied asset would raise it further, in priority order:

1. **Team portraits and studio/process footage** (Scene 11, `/about`). Currently
   tactile placeholder planes. Real photography is the single biggest upgrade —
   it is the only scene about people.
2. **Project hero imagery and galleries** (Scene 10, `/work/[slug]`). Three to
   five approved case studies with stills, and one sculptural hero form per
   flagship project if you want the artefacts to be project-specific rather than
   silhouette variants.
3. **A product or subject for the Matter Lab plinth** (Scene 8). Right now an
   abstract capsule stands in for whatever AG actually shoots.
4. **Identity artwork for the Identity Engine modules** (Scene 5). The modules
   are coloured planes; real type specimens, marks and colour fields would make
   the scene concrete.
5. **Optional:** a bespoke sculptural form for the Evidence Chamber, and a
   recorded ambient bed if you would rather not use the generative one.

Supply as glTF/GLB (Draco or Meshopt) with KTX2 colour textures, real scale,
consistent axes and pivots, plus explicit mobile variants.

Tests actually run:

- **Unit (Vitest): 31 passed.** Brand path integrity, glyph geometry proportions
  and winding, counter-space preservation, scene range maths, camera path
  continuity and roll limits, token parity between CSS and the WebGL palette,
  fixture integrity, enquiry validation.
- **End-to-end (Playwright): 98 passed, 1 skipped**, across desktop Chromium,
  mobile WebKit (iPhone 13) and a forced-reduced-motion project. Covers all seven
  routes, the 404, deep links to scene hashes, project portals and browser back,
  the contact form's success and error paths, keyboard traversal, 320 px reflow,
  the no-WebGL fallback and the reduced-motion tier.
- **axe-core: no serious or critical violations** on `/`, `/work`, `/services`,
  `/about`, `/contact` and `/privacy`, in all three projects.
- `tsc --noEmit` (strict, `noUncheckedIndexedAccess`), ESLint and `next build`
  all pass clean.

The one skipped test is the skip-link tab-order check on WebKit, which only tabs
to links when the operating system's "Tab highlights each item" preference is on;
Playwright cannot set it. Verified by hand instead.

### Not yet measured

**Core Web Vitals and frame rates have not been measured on real devices or in
the field.** LCP, INP, CLS and the 60/45/30 fps floors need a staging deploy and
representative hardware before anyone claims they pass. Lighthouse CI is not
wired up, and there is no CI bundle-size gate yet. The numbers above are
build-time budgets, which is a different thing.

## Accessibility notes

- Every scene headline, capability link, project link and CTA is server-rendered
  into the initial HTML. Only the project overlay reads the URL, and it is the
  only thing behind a Suspense boundary — deliberately, because `useSearchParams`
  opts its whole boundary out of static prerendering.
- The canvas is `aria-hidden`. It illustrates; it never informs.
- Text contrast: `--text-tertiary` sits at the 0.58 alpha that clears 4.5:1 on
  the ink surface. Lowering it fails AA on the eyebrows, form hints and legal
  line. There is a comment in `tokens.css` saying so.
- Sound is muted by default, the control only appears after an explicit gesture,
  and the bed is generative and decorative.
- The project overlay traps focus while open, restores it on close, and closes on
  Escape and on browser back.

Still to do by hand before launch: VoiceOver + Safari, NVDA + Chrome, and 200%
zoom passes.

## Decisions the client needs to make

1. **The public brand name.** The brief says *AG Designs*; stakeholders have also
   said *AG Design Studios*. It is a single value — `siteSettings.brandName` in
   `src/lib/content/fixtures.ts` — and changing it renames the site everywhere.
   `AG Designs` is the current placeholder.
2. **Logo usage approval** — see "The brand contract" above.
3. **Which case studies are public**, with permission for client names, imagery
   and any figures.
4. **Where enquiries go** (`CONTACT_WEBHOOK_URL`).
5. **The privacy policy.** `/privacy` currently carries clearly labelled
   placeholder copy that must be reviewed and replaced.
6. **Analytics.** The event contract exists in `src/lib/analytics/events.ts` and
   fires nothing until a consented sink is attached with `setAnalyticsSink`. No
   third-party tracker ships in this build.
